# Architecture

```
 hotkey / wake word
        |
        v
  [audio.capture] --mic blocks--> VAD endpointing --> [stt.whisper] (CPU, int8)
        |                                                  |
        | level                                            v text
        v                                            [llm.brain]
  [overlay.client] <--state/level/text--  core  --------> fast path (regex) or Ollama (GPU)
   (separate process,                 ^                     |
    token-auth loopback)              |             tool calls (validated)
                                      |                     v
                              [safety.gate] <------- [safety.policy] (config only)
                                      |  confirm? --> system readback --> real "yes" (voice / hotkey)
                                      v
                                [tools.*]  [screen.*: UIA -> OCR -> VLM]  [control.*]
                                      |
                                      v sentences (streamed)
                                [tts.speaker] --> [audio.playback] --level--> overlay
```

* **State machine** (`core/state.py`): IDLE → LISTENING → TRANSCRIBING → THINKING → (ACTING) → SPEAKING → IDLE, plus ERROR / PAUSED. Transitions publish `state` events on the bus; the overlay client and wake-word pause/resume subscribe.
* **Brain** (`llm/brain.py`): persona + remembered facts + rolling summary + short history → Ollama `/api/chat` (streaming, tools, `think=false`). Sentences are split incrementally and handed to TTS as soon as each completes. Tool calls go: schema validation → `SafetyGate` → execution (thread pool with timeout) → result back to the model. Results from untrusted sources (web, screen, files) are wrapped as data and scanned for injection phrasing.
* **Fast path** (`llm/fastpath.py`): regexes for time, timers, open app, volume, media, reminders, notes. They bypass the LLM entirely and still go through the gate. `match_smalltalk` answers a bare "thanks" / greeting / goodbye with a varied canned line.
* **Latency design** (D21): the system prompt is kept byte-identical between turns and `Brain.warm()` primes Ollama's prompt cache with the real prompt and tool list at start-up and whenever the model was unloaded or idle (`rewarm_if_cold`, triggered when the user starts speaking); the rolling summary runs on a background thread; start-up warms the speech model, voice, LLM and app list in parallel. A batch of side-effect-free tool calls runs concurrently (gating stays sequential), and a slow tool gets a spoken "one sec" after `llm.filler_after_s`.
* **Conversation** (`app.py`): after a reply the mic reopens without a wake word; the listening window grows with each back-to-back turn (`followup_patience_s`, capped by `followup_window_max_s`); talking over EV stops it (`audio/interrupt.py`) and the interrupting speech is carried into the next recording. With `conversation.continuous_mic = true` one `SharedMic` stream stays open for the whole conversation and the monitor and the recorder both listen to it (no re-open between turns, nothing lost at the hand-off); the wake word's own stream resumes only after it is closed.
* **Safety** (`safety/`): `Policy` decides allow/confirm/block from `config/policy.toml` and the arguments only. `SafetyGate` performs the confirmation as a separate system-driven step with the exact action read back; with no asker it fails closed. A kill event denies everything.
* **Screen** (`screen/`): UI Automation tree first, RapidOCR second, `qwen2.5vl:3b` VLM last (D11). The VLM path unloads the chat model first and itself immediately after (`keep_alive=0`), so VRAM never holds both.
* **Control** (`control/`): pyautogui/pywinauto actions re-check the resolved UIA element (password flag, sensitive window) right before acting. `ScreenAgent` is the bounded observe→act→verify loop (default 8 steps, stuck-detection, kill aware).
* **Overlay** (`overlay/`): independent process. Core → overlay is newline-delimited JSON over `127.0.0.1` with a per-session token delivered via stdin. The overlay exits when the core connection closes; the core restarts it (rate limited) if it dies.
* **Memory** (D22, D23). Facts, people, projects and daily summaries are Markdown files in a vault folder (`memory/vault.py`, `[vault]` in `ev.toml`); EV writes only inside `<vault>/EV` and reads the whole vault through a rebuildable SQLite FTS5 index (`memory/vault_index.py`, bm25, polled for edits, no watcher dependency). SQLite (`memory/store.py`) still holds reminders, notes and kv, plus `fact_records`: the SHA-256 of every fact line EV wrote. A line of `Facts.md` reaches the system prompt only if it matches a record; the `source:` label in the file is never believed. Unmatched lines are "unconfirmed facts" (ordinary notes, reachable by `recall` wrapped as untrusted, kept by a spoken yes via `keep_fact`). With `vault.enabled = false`, or if the folder can't be used, facts fall back to the SQLite `facts` table. The user's first facts are seeded once from `config/seed_facts.toml` (`memory/migrations.py`), so `persona.md` is character and rules only. No vector DB. `kv.last_artifact` records the last screenshot or note EV made.
* **Proactive** (`proactive/rules.py`, `proactive/probes.py`, `proactive/engine.py`, `config/proactive.toml`, D27): `ProactiveEngine` runs on its own thread (tick every 2 s; process and file sources every 10 s), looks outside its lock, queues what is due, and hands each item to its actions only if no guard objects (state is idle, not snoozed, not quiet hours, no full-screen app, no call, someone at the keyboard, under the hourly cap). Actions are `say` (`EVApp.say_direct`), `notice` (the overlay `notice` message) and `skill` (`Brain.run_skill_proactive`, every step gated with `ask_allowed=False`). Probes are plain functions so tests swap in fakes.
* **Dashboard** (`dashboard/server.py`, `hub.py`, `backend.py`, `settings_schema.py`, `localconf.py`, `static/`, D28): `EVApp` feeds a `Hub` (state, turns, tool results with the gate's decision, proactive events) and, if `[dashboard] enabled`, starts a `DashboardServer` on a free loopback port. The server only does transport and checks (one-time link to cookie, `Host`, `Origin`, JSON, size) and calls an `AppBackend`, which reads state, applies allow-listed settings (to `ev.local.toml`, live where safe), swaps the voice or chat model, and asks `Brain` to run skills or `forget_fact` / `keep_fact` through the gate. There is no route that writes `policy.toml`.
* **Skills** (`skills/store.py`, `skills/runner.py`, `skills/*.toml`, D26): `SkillStore` reads and checks the files (and writes new ones inside `skills/` only); `Brain` matches a trigger phrase before the other fast-path patterns, registers `run_skill` (name enum from the files; re-primes the prompt cache once when the list changes) and the voice-only `save_skill` / `manage_skill`, and runs each step through `Brain._execute` with `source="skill"`, so each step has its own validation, gate decision and provenance check. `skills/runner.py` is the pure step loop.
* **Context** (`context/snapshot.py`, `context/calendar.py`, D25): per model turn, `Brain` asks `ContextSnapshot.build(user_text)` for a short block (foreground app, next event, recent files, battery, git branch; only what the request is about) and appends it, wrapped as untrusted data, to the latest user message, so the system prompt stays byte-identical. The calendar (`none` by default, `.ics` or Outlook, read-only) refreshes on its own thread and is only read from a cache on the request path.
* **Provenance** (`safety/provenance.py`, D23): `Brain` keeps a `TurnState` (your last three utterances, whether untrusted text was seen this turn). For `remember_fact` / `forget_fact` it computes an escalation reason and passes it to `SafetyGate.check(..., escalate=)`, which can only turn an allowed call into a spoken confirmation. `Policy.evaluate` itself is unchanged: config and arguments only.
* **Files** (`open_file`, D22): opens the last file EV made, or a path, with the Windows default app. Policy limits it to `[files] open_dirs` (`data/notes`, `data/sandbox`, the screenshot folder; `{name}` placeholders are filled from `ev.toml` by `Config.places()`) and to the types in `open_extensions`; the tool re-checks the file it resolved itself.
* **Degradation**: Ollama down → spoken message; configured model missing → fallback model; no mic → spoken message; TTS or speaker failure → logged, EV keeps running; overlay failure → ignored.
