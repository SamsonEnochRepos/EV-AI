# Changelog

All notable changes to this project are documented in this file.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- **The pill is now a dynamic island** (`ev/overlay/`). A black pill that stays at the top of the screen (`overlay.idle_visible`) with two eyes that follow the mouse pointer (`overlay.follow_cursor`), blink, squint happily when the pointer is over it or when EV finishes talking, and look up and about while it thinks. It springs open to a wider shape while EV listens or speaks, with level bars either side of the eyes, half-opens while it is thinking, and rings itself in the accent colour (`overlay.accent`) while EV works on your screen. Display mode no longer shows a separate card: the same body grows downward to hold the text and folds back after `display_linger_s`. Still click-through and never takes focus; the window is fixed-size and 0% CPU is traded for a 30 fps idle tick (skipped when nothing changed). Animation maths (`Eyes`, `Spring`, `island_shape`, `place_window`) is in `overlay/anim.py` with `tests/test_island.py`; `Pill.settle()` renders a state at rest for tests and the overlay eval.
- **Dashboard restyled as a HUD** (`ev/dashboard/static/`): rail navigation, a canvas orb (`orb.js`) that reacts to EV's state and live voice level, a live feed, tiles with a display-mode switch, skills you can run from the live page, and three themes (Crimson, the default, Arc blue, Nebula) chosen per browser. The server now replays recent events to a page that connects late and streams audio levels (`level`, throttled to 15 Hz, only while a page is watching). Same rules as before: strict CSP, text set with `textContent`, no inline styles or scripts.

### Added
- **Island/dashboard tests and eval updates**: `tests/test_island.py` (eyes, springs, shape, placement), event-replay and audio-level tests plus an `orb.js` safety check in `tests/test_dashboard.py`, display-mode tests rewritten for the fixed-size island window, and `ev/evals/overlay_eval.py` moved to `Pill.settle()` with the hide-when-idle check run under `idle_visible = false`. `[overlay]` in `ev.toml` gained `wide_width`, `wide_height`, `idle_visible`, `follow_cursor`, `eye_color` and `accent`; `width`/`height` are now the resting pill (116x34).
- **Lookup planner**: on a question-shaped turn that no fast-path rule matched, one short tool-less model call (`Brain._plan_lookup`, `llm.lookup_planner`, on by default) decides whether the web is needed and writes a standalone keyword query from the last two turns, so a follow-up like "what was its name?" or garbled speech still searches the right thing. The `3B` model rarely called `web_search` by itself and answered from memory. Any failure falls back to the old tool-calling path. `looks_like_question` in `fastpath.py` gates it (chat aimed at EV is skipped).
- **Groundwork, nothing wired in** (D30): `scripts/finetune/export_data.py` (opt-in, redacted, dry-run by default; drops turns that quoted web, screen, file or note text) with 4 tests, `scripts/finetune/qlora_qwen25_3b.ipynb` (an outline, not run), `docs/design/SPEAKER_VERIFICATION.md` and `docs/design/PHONE_ACCESS.md`.
- **More conversational persona** (D29): Evie ends with a question only when you shared something (never two), offers a next step now and then, may say "boss" occasionally (never as the first word) or whatever you ask to be called ("call me Chief" saves `preferred_name`), ties in what she knows lightly, and treats the context block as background. Persona eval 30 to 41 prompts with new checks and rates (question, boss, offer, memory callbacks). A code guard (`drop_name_opener`) also removes a vocative name from the first sentence of a reply. Honest result: "boss" and the two-question habit changed as intended; the 3B model still asks a question in about 7 of 10 replies and rarely calls back to memory, with either persona.
- **Dashboard** (D28): say "open the dashboard" (or use the tray) for a local page on `127.0.0.1` with a live view (state, conversation, every tool call with the gate's decision and timing, timers, what EV said on its own), settings, a voice and chat-model switcher, skills (run, edit, delete), memory (verified facts, unconfirmed lines, search) and the policy (read-only). Each visit needs a one-time sign-in link; the page cannot change `policy.toml` or anything that widens access; only an allow-list of 30 tuning settings is editable, written to `config/ev.local.toml`. Running a skill, forgetting a fact and confirming one go through the same gate as a spoken request (a risky one still asks out loud). `[dashboard] enabled` / `port` in `ev.toml`; `llm.vram_budget_gb`; `[proactive]` guard overrides; `open_dashboard` (voice only); `Speaker.swap_engine`; `Brain.on_tool_result`; `Brain.run_skill_for_user`. Security suite: 16 new `dashboard:` cases.
- **Memory in a vault of Markdown files, with a search index** (D23). Facts, people, projects and daily summaries are plain files in `Documents\EV-Vault\EV\` (`[vault]` in `ev.toml`; Obsidian optional). EV writes only inside that folder (a junction or `..` out of it is refused, and `policy.toml` `write_dirs` is a second lock) and reads the whole vault through a rebuildable SQLite FTS5 index ranked with bm25 (`python -m ev.memory.vault_index --rebuild`). New `recall(query, when)` tool and fast-path phrasings ("what did I say about X last week", "what's in my notes about X", "look up X in my notes" never goes to a search engine); results are wrapped as untrusted data. `remember_fact` / `forget_fact` write to the vault (with an optional `about` person or project); old SQLite facts are moved in once. Phrasings like "remember that...", "..., keep that in mind", "don't forget ..." are handled by the fast path.
- **Memory writes need provenance** (D23). A model-made `remember_fact` / `forget_fact` is saved silently only if its words are words you said in your last three utterances and nothing from the web, the screen, a note or a file was seen this turn; otherwise EV reads it back and needs a spoken yes (`ev/safety/provenance.py`, escalation-only `SafetyGate.check(..., escalate=)`). Values are cut to 200 characters, stripped of tags, `[[links]]`, backticks and Markdown structure, and refused if they read like an instruction. Security suite: 19 new cases (poisoned web result, screen text and vault note, a poisoned paraphrase in history, forged lines, sanitising, confinement).
- **The vault's labels are never trusted** (D23). Each fact line EV writes is also recorded (SHA-256 of the exact line) in SQLite; only lines that match a record reach the system prompt. A hand-edited, pasted or forged line (even one that says `(source: user said)`) is an *unconfirmed fact*: a normal note, found only through `recall`, until you say "review my unconfirmed facts" and answer yes to each (`keep_fact`, voice only, always confirmed).
- **EV can speak up on its own** (D27): `config/proactive.toml` rules (a time of day, a calendar event coming up, a build tool that ran a while has finished, a file that finished downloading, low battery, a long stretch in one app, or an event from elsewhere in EV) can say a line, show a short card, or run a skill. Starter rules: low battery, long build finished, a weekday morning brief, and a meeting-soon rule that ships off. It holds its tongue during quiet hours, full-screen apps and presentations, calls, a turn or confirmation, when nobody is at the keyboard, past four spoken lines an hour, and while snoozed ("quiet for an hour", "you can talk again"); a held line is dropped after ten minutes instead of arriving stale. A skill started this way never asks a question: a step that would need your yes is refused. New overlay `notice` message for silent cards.
- **Skills** (D26): routines made of ordinary tool calls, one TOML file each in `skills/` (`[skills]` in `ev.toml`). "Work mode", "work mode with jazz", "morning brief" and "wind down" ship. They run from the fast path (the whole sentence is a trigger phrase), from the model's `run_skill` tool, and later the dashboard; **every step goes through the safety gate on its own**, a refused step stops the skill and says which one. Teach by doing, by voice only: "save that as <name>", "also run it when I say ...", "rename the skill ...", "what skills do I have", "delete the skill ..." (deleting needs a spoken yes). The model cannot create or change skills, and cannot run one you never mentioned. New `list_reminders` tool ("what are my reminders") and `ToolRegistry.unregister`.
- **Context snapshot** (D25): a few lines about what is going on (the app and window you are in, the next calendar event, files that just appeared in Downloads / Desktop / screenshots, battery, the git branch of a repo open in your editor) are put beside your request on the model path, only the lines the request is about. `[context]` in `ev.toml`; every signal can be switched off; a sensitive window shows the app only; the block is wrapped as untrusted data and never touches the system prompt. Calendar is off until you set `calendar_source` to `ics` or `outlook` (read-only); `get_agenda` exists only then. Builds in about half a millisecond (`python -m ev.evals.bench context`).
- **Facts about you, rebuilt from your own messages** (D24): `config/seed_facts.toml` grew from 8 to 17 facts (sign-off name, student and hackathons, project names, tools and conda-only rule, how you like explanations, what you want from Evie, "EV / Evie, never Eevee"). `apply_seed_updates` adds new seed keys to an existing vault on the next start without overwriting anything or bringing back a fact you forgot.
- **"Do you remember ...?" and "you remember ..., right?"** now search your notes and facts and say honestly when there is nothing, instead of letting the model play along (D24).
- `Tool.llm_visible`: voice-only tools (`keep_fact`) are not in the model's tool list and a model-made call to one is refused.
- `Brain` refreshes Ollama's prompt cache once in the background when a fact changes (`refresh_prompt_cache`).
- Config: `[vault]` section, `memory.fact_max_chars`, `memory.fact_overlap_min`, `memory.seed_file`; optional `vault` extra (`pyyaml`) in `pyproject.toml`; `python -m ev.memory.vault_index --rebuild | --query "..." --when "..."`; a "Memory" section in the README.
- `.gitignore`: `*.evtmp` (vault write temp files), `EV-Vault/` (a vault inside the repo is the user's notes), and the top-level `/evals/` output folder.
- Memory eval now runs the fast path (what the app does) and reports the model-only `remember_fact` rate separately (`model_only_remember_calls_of_3`, currently 0, see D23).
- **"Open it" / "open the screenshot you just took"** (D22): new `open_file` tool opens the last screenshot or note EV made (`kv.last_artifact`), or a path, with the default app. Policy limits it to `[files] open_dirs` and `open_extensions` in `policy.toml` (no executables or scripts), and the tool re-checks the file it resolved. `take_screenshot` and `take_note` record what they made; `take_note` now also appends to `data/notes/<date>.md` so a note can be opened (SQLite stays the record). `{screenshots}`/`{skills}` placeholders in `policy.toml` folder lists are filled from `ev.toml` (`Config.places()`).
- **Persona facts moved to memory** (D22): what Evie knows about the user is in `config/seed_facts.toml` and is seeded into memory once at first start-up (`ev/memory/migrations.py`); an existing fact is never overwritten and a fact you later forget stays forgotten. `config/persona.md` is now character and rules only. `memory.max_facts_in_prompt` 12 → 16.
- **Faster first reply**: `Brain.warm()` primes Ollama's prompt cache with the real system prompt and tool list at start-up, and `Brain.rewarm_if_cold()` reloads the model in the background while you are still speaking if it was unloaded (screen reading swaps it out) or idle for `llm.rewarm_after_s` (90 s). Measured with `qwen2.5:3b`: first speech 0.23 s after the real-prompt warm-up vs 1.04 s after the old bare "hi" warm-up. Start-up now warms the speech model (with a throwaway decode), the voice, the LLM and the app list in parallel.
- **Smalltalk without the model**: a bare "thanks", greeting or goodbye gets a varied instant reply (`match_smalltalk`). "yes", "okay" and "later" are excluded on purpose because they can answer a question.
- **"One sec" for slow tools**: if search, weather or a screen read is still running after `llm.filler_after_s` (1.3 s, set 0 to disable), EV says a short varied phrase instead of going silent. It is system text and is not stored in history.
- **Parallel tool calls**: when one model turn asks for several side-effect-free tools (weather, search, time, memory, timers, reminders) they run concurrently via `ToolRegistry.run_many`; UI tools keep their order and every call is still gated one at a time before any runs. The tool pool grew from 2 to 6 workers.
- **More patient follow-ups**: the listening window grows by `conversation.followup_patience_s` (2 s) per back-to-back turn up to `followup_window_max_s` (15 s); "hmm" / "um" in a follow-up window no longer reaches the model; `conversation.turn_gap_ms` makes the 300 ms pause before the mic reopens configurable.
- `Tool.direct`, `llm.direct_tool_replies` and `tts.first_clause_chars` (with `SentenceSplitter.feed_ex`): speak a tool's own result line without a second model call, and speak a long first sentence from its first comma. **Both are off**: measured over 6 action turns each, direct replies were no faster (median 0.30 s vs 0.28 s, the warm prompt cache makes the second call nearly free) and less natural, and first speech already starts about 0.25 s after the question. Kept for slower hardware.
- **Continuous mic** (`conversation.continuous_mic`, off by default): `SharedMic` keeps one input stream open for a whole conversation and fans it out to the barge-in monitor and the recorder, so the device isn't closed and reopened between turns and nothing is lost at the hand-off. Listeners subscribe immediately and unsubscribe on close or garbage collection; if the stream can't be opened EV falls back to one stream per turn. Smoke-tested on the real microphone; barge-in with a real voice over speakers is not verified, so it stays off until tried.

The mode is remembered across restarts (`overlay.display_mode` sets the default), the card stays `overlay.display_linger_s` after EV finishes, and long replies scroll so the newest words stay visible. ### Changed
- **`web_search` favours fresh results**: a query that asks for something recent (latest, recently, today, news...) tries DuckDuckGo's past-week filter first, then dated news, then the past month, because plain text search ranked last year's storm as the answer. Result lines now carry their date and the model is told to trust the newest.
- The system prompt now carries the date and part of the day instead of the minute-level clock, so Ollama's cached prompt stays valid between turns (the old line changed every minute and invalidated the cache). "What time is it" is answered by the fast path / `get_time_date`.
- The rolling-summary model call runs on a background thread instead of delaying the end of every eighth turn, and re-warms the prompt cache afterwards.
- One fast-path match per turn (it ran twice), the tool-schema token estimate is computed once per registry change, and the model's HTTP stream is closed as soon as the reply cap is reached.
- Whisper decodes with `without_timestamps=True` (utterances are at most 15 s).
- Start-menu shortcuts are cached for five minutes (the folder walk ran up to four times per app launch) and rebuilt once if an app isn't found; weather reuses one HTTP connection and caches geocoding (24 h) and forecasts (5 min).
- Media-key replies are phrased as speech ("Skipping ahead.") instead of "Done: next."
- `.gitignore` reorganised into sections; also ignores local audio (`*.wav`, `*.flac`, `*.mp3`), model/array files (`*.npz`, `*.npy`, `*.pt`, `*.pth`), `*.log`, SQLite WAL files, `.env.*`, `venv/`, editor and OS leftovers. Nothing already tracked is affected.
- Docs: `ARCHITECTURE.md`, `SECURITY.md`, `README.md` and `PROJECT_DOCUMENTATION.md` describe the latency design, the new config keys and the current test status (373 passing).
- Tests: `tests/test_latency.py` is new (direct replies, parallel and gated batches, filler, smalltalk, clause chunks, warm-up, background summary); `tests/test_audio_overlay.py` covers `SharedMic` fan-out, eager subscribe and cleanup; three integration tests cover the continuous mic (opened once per conversation, off by default, fallback on failure); three integration tests cover the growing follow-up window, hesitation sounds and instant smalltalk; the integration helper marks its fake Ollama client warm so a background re-warm can't consume a scripted reply; `test_ollama_down_gives_spoken_message` uses "how was your day" because "hello there" is now smalltalk.

- `config/ev.toml`: `tts.engine` is now `"piper"` (`en_US-hfc_female-medium`) instead of `"kokoro"`; Kokoro stays available as an option.

- Config: `hotwords` gain "YouTube" and "display mode"; `interrupt_margin` 2.0 -> 1.5. Added `tests/test_interrupt.py` and the recorded-levels fixture `tests/data/echo_laptop_speakers.json` (levels only, no audio).
- Overlay wire format is UTF-8 (`ensure_ascii=False`); `Pill` now sizes itself from its content and positions the pill by anchor inside a wider window. Tests added for display mode (`tests/test_display_mode.py`, plus integration turns in `tests/test_integration.py`).
- `read_screen` hint now asks for one short casual sentence instead of one or two.
- Speech recognition: default model is now `distil-small.en` (beam 3, 6 threads) instead of `base`; input audio is DC/rumble filtered and level-normalised before decoding, Whisper gets `hotwords` for EV's common vocabulary and a temperature fallback, and the pre-speech buffer grew from 300 to 480 ms (`audio.pre_roll_ms`). Costs about 1.3 s more per turn than `base`; set `stt.model = "base"` to trade back.
- Voice: default TTS engine is Kokoro (`af_heart`, speed 1.05) with a 90 ms pause between sentences (`tts.sentence_pause_ms`); EV falls back to Piper if Kokoro can't load.
- Replies: `llm.reply_max_sentences = 2` is now enforced in `Brain` (generation stops once reached; 6 when the user asks for detail), `num_predict` dropped from 220 to 110, and the persona's speaking rules were rewritten for a casual, answer-first voice.

- Evie's voice is now the Piper voice `en_US-hfc_female-medium` (`tts.piper_voice` in `config/ev.toml`); the voice is also listed in `scripts/download_models.py`. Its training data is CC BY-NC-SA 4.0 (non-commercial).

- Defaults from measurements: STT `base` (RTF 0.23 vs 0.65), VLM `qwen2.5vl:3b` (5/5 vs 2/5), VAD silence window 550 ms, persona tool guidance (tool accuracy 81.8% -> 92.4%).
- Runtime is offline for models (`local_files_only`, `HF_HUB_OFFLINE`); `web_search` pinned to the DuckDuckGo backend.
- Security eval suite: 88/88 deterministic checks pass, 0 confirmation bypasses. 123 unit tests pass.
- Ruff line length set to 120; E501 and UP042 ignored.
- Recorded the LLM speed/VRAM benchmark in `docs/DECISIONS.md` (D4): qwen3:4b rejected (27.6% spills to RAM, 28 tok/s); qwen2.5:3b and llama3.2 fit fully in VRAM at about 77-80 tok/s.
- Control tools (click, type, press keys, paste) are `safe` at tool level; risky targets and key combos escalate to confirmation by argument.

- **Tool schemas sent to the model no longer carry `maxLength`** (still enforced when a call comes back) and the history budget estimate now uses 4.0 characters per token instead of 3.5 (D23). Measured against Ollama's own count, the 3.5 estimate over-counted the fixed prompt by about 35%, and with the new tools it said the prompt alone filled the budget, which would have dropped all conversation history every turn.
- The vault index deletes a note's old chunks by rowid range instead of scanning the FTS5 table by path (rebuilding 2000 notes: 22 s → 6.75 s) and releases its lock between notes so `recall` isn't stalled by a first big index.
- `llm.num_ctx` 4096 → 6144 and `memory.max_facts_in_prompt` 16 → 24 (D24): measured 100% on the GPU with unchanged speed.
- The fast path ignores a couple of leading fillers ("Yeah, so", "okay", "um") that Whisper keeps in front of a request.
- `Brain._PARALLEL_SAFE` no longer includes `remember_fact` / `forget_fact` (they can need a spoken yes and must run one at a time).

### Fixed
- The greedy "open …" fast-path pattern turned "Open the particular screenshot you just took" into `open_app("particular screenshot you just took")` (D22). Phrases that point at something (it, that, this, last, just took, screenshot, file, pdf, image...) now never become an app lookup: "open it" and "the screenshot (you just took)" go to `open_file`, the rest to the model. "file explorer" and "one note" still open as apps.
